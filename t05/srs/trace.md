# Трассировка рекурсивной функции F(n)

```java
static int F(int n) {
    if (n <= 1) return 1;
    return n * F(n - 1);
}
```

## 1. Базовый случай и шаг рекурсии

- **Базовый случай:** `n <= 1` → возвращается `1`. Рекурсия здесь прекращается.
- **Шаг рекурсии:** `n * F(n - 1)`. Задача сводится к вычислению того же факториала для меньшего аргумента.

## 2. Трассировка F(4)

Вызовы идут вниз по стеку, значения возвращаются вверх.

| Вызов  | Глубина | Возвращает |
|--------|---------|------------|
| F(4)   | 1       | 4 × 6 = **24** |
| F(3)   | 2       | 3 × 2 = **6**  |
| F(2)   | 3       | 2 × 1 = **2**  |
| F(1)   | 4       | **1** (базовый случай) |

Порядок возврата: F(1) → F(2) → F(3) → F(4). Результат: F(4) = 24.

## 3. Замена условия на `n == 1`

Код становится таким:

```java
static int F(int n) {
    if (n == 1) return 1;
    return n * F(n - 1);
}
```

При вызове F(-1) проверка `n == 1` ложна, поэтому выполняется шаг рекурсии:

F(-1) → F(-2) → F(-3) → F(-4) → …

Значение `n` уменьшается и никогда не станет равным 1, поэтому базовый случай не достигается. Каждый вызов добавляет новый кадр в стек, и в итоге стек переполняется.

**Ошибка:** `java.lang.StackOverflowError` (переполнение стека вызовов).

Тот же механизм сработает и при F(0). Поэтому условие `n <= 1` надёжнее: оно защищает от любых значений меньше 1.
