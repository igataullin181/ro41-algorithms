# Трассировка: строки, Split, TryParse, конкатенация

## 1. Trim и Split

Входные данные: s = " Иванов Пётр;70;85;x "

- Исходная s: " Иванов Пётр;70;85;x " (длина 21)
- После s.Trim(): "Иванов Пётр;70;85;x" (длина 19)

После Split(';') получаем массив из 4 элементов:

- [0] "Иванов Пётр" (длина 11)
- [1] "70" (длина 2)
- [2] "85" (длина 2)
- [3] "x" (длина 1)

## 2. TryParse для line = "Иванов Пётр;70;85;x"

- [0] "Иванов Пётр": TryParse = false, out = 0
- [1] "70": TryParse = true, out = 70
- [2] "85": TryParse = true, out = 85
- [3] "x": TryParse = false, out = 0

TryParseScores вернёт false: часть "x" не является числом, значит проверка оценок не проходит. Точный результат зависит от кода метода. Если пришлёте TryParseScores, уточню трассировку.

## 3. Конкатенация и StringBuilder

Цикл s = ""; for (i = 0; i < 4; i++) s += i;

- i = 0: создаётся "0", результат "0". Новых объектов: 1
- i = 1: создаётся "1", результат "01". Новых объектов: 2
- i = 2: создаётся "2", результат "012". Новых объектов: 2
- i = 3: создаётся "3", результат "0123". Новых объектов: 2

Итого: 7 объектов string.

StringBuilder с sb.Append(i): в .NET 5+ число пишется прямо в буфер, промежуточных string нет. Итого: 0 объектов string в цикле. Строка создаётся один раз при вызове sb.ToString(): "0123".

## 4. Почему s не изменилась после s.ToUpper()

Строки в C# неизменяемы (immutable). ToUpper() возвращает новую строку и не меняет исходную. Без присваивания результат теряется. Правильно: s = s.ToUpper();
